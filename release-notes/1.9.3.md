# 1.9.3

## Исправлено: недоступность сайтов на Cloudflare (curseforge.com, rutracker.org и др.)

После расширения диапазонов Cloudflare в `route_address` туннеля (для Discord-медиа, 1.8.11) TCP-трафик к Cloudflare стал попадать в sing-box. При этом DNS-сервер `local` возвращал реальные **IPv6**-адреса (`2606:4700::…`), для которых в системе нет маршрута (`Network is unreachable`). Браузер пытался подключиться по IPv6 и не мог открыть сайт. В логах туннеля — массовые `dns: lookup failed ... empty result`.

В DNS-конфиг sing-box добавлен `strategy: "ipv4_only"` (Linux и Windows):

- сайты на Cloudflare и другие домены получают только IPv4-адреса, которые маршрутизируются;
- ответ на AAAA — `NOERROR` без записей, браузер сразу использует IPv4;
- FakeIP для доменов туннеля (включая IPv6-диапазон `fd7a:…`) продолжает работать: его выдаёт правило `fakeip`, а не `local`.

## Проверено

- Конфиг, сгенерированный кодом релиза, проходит `sing-box check`.
- На тестовом sing-box: `curseforge.com` → `104.17.29.3/104.17.30.3`; `rutracker.org` → `10.249.0.5` (FakeIP); `protondb.com` → `10.249.0.107` (FakeIP); AAAA — пустой ответ.
- `py_compile`, `sh -n`/`bash -n`, `build-cmd.py --check`, парсинг PowerShell 5.1, PSScriptAnalyzer (Error), тест Pester на `ipv4_only`.

## Не проверено

- Живая загрузка сайтов в Firefox после обновления (нужен сам браузер и провайдер пользователя).
