# 1.8.7

Хотфикс Windows-версии: после установки среды доступ к спискам
(`lists\autohostlist.txt` и другим) был запрещён даже администратору —
«Access to the path ... is denied» при запуске. Изменений в Linux нет
(версия выровнена для самообновления и единого релиза).

## Исправлено (Windows)

- **Пустой DACL у всех файлов, существовавших на момент установки прав.**
  `Protect-Directory` вызывала icacls одной командой:
  `icacls <каталог> /T /inheritance:r /grant:r *S-1-5-18:(OI)(CI)F ...`.
  ACE с флагами наследования `(OI)(CI)` валиден только для каталога: файл
  наследовать не может, и icacls **молча игнорирует** такой grant на файле
  (код возврата 0, «успешно обработано», ACE не добавляется). При этом
  `/inheritance:r` с `/T` срезал унаследованные ACE со всех дочерних
  файлов. Итог: `winws2.exe`, `WinDivert*.dll/sys`, `lua\*.lua` и все
  списки оставались с пустым DACL — доступ запрещён всем, включая
  администраторов и SYSTEM. `winws2.exe` не мог даже запуститься.
  Файлы, созданные уже после установки прав (`winws2.args`), наследовали
  права от каталога и работали, поэтому часть системы выглядела живой.
- Исправленная схема: сначала `icacls <каталог> /reset /T /C` (дочерние
  файлы сбрасываются на наследование от каталога), затем grants с
  `(OI)(CI)` задаются **только на сам каталог** — дети получают их
  наследованием (у файлов появляются ACE с флагом `(I)`). Двухпроходный
  fallback для старых сборок icacls сохранён и согласован с новой схемой.

## Восстановление системы, повреждённой предыдущей версией

Если 1.8.6 уже оставила файлы с пустым DACL (ошибка «Access to the path
... is denied» остаётся и после обновления скрипта), выполните один раз
от администратора:

```
icacls "C:\Windows\System32\Zapret2Windows" /reset /T /C
icacls "C:\Windows\System32\Zapret2Windows" /inheritance:r /grant:r *S-1-5-18:(OI)(CI)F /grant:r *S-1-5-32-544:(OI)(CI)F /grant:r *S-1-5-32-545:(OI)(CI)RX
```

Затем запустите установку (пункт [1]) заново.
