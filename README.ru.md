# Zapret2 Windows / Linux — системный контроллер

[English version](README.md) · [Аудит безопасности](SECURITY.md) · [Лицензия](LICENSE)

Контроллер для [`bol-van/zapret2`](https://github.com/bol-van/zapret2)
(релиз v1.0.6). Делает две вещи:

1. **Обход DPI** для всех приложений системы — сайты, которые провайдер
   замедляет или обрывает, открываются напрямую, без потери скорости.
2. **Туннель** для сайтов, которым обход DPI не помогает (адрес заблокирован
   целиком или сервис сам не пускает из России): через Proton VPN Free или
   свой сервер. В туннель идут только выбранные сайты.

| Платформа | Что скачать | Движок обхода |
|---|---|---|
| Linux | [`zapret2-linux.sh`](zapret2-linux.sh) — один файл | `nfqws2` + nftables/iptables |
| Windows | [`Zapret2Windows.cmd`](Zapret2Windows.cmd) **или** [`Zapret2Windows.ps1`](Zapret2Windows.ps1) — любой один файл | `winws2` + WinDivert |

Версия скриптов — 1.8.4. Интерфейс — на русском языке.
Скачивать лучше со страницы [последнего релиза](https://github.com/HikariRisser/Zapret2Scrpt/releases/latest).

## Быстрый старт

### Linux

Нужен один файл — `zapret2-linux.sh`. Скачайте его со страницы
[релиза](https://github.com/HikariRisser/Zapret2Scrpt/releases/latest) и запустите:

```bash
sh zapret2-linux.sh
```

Скрипт сам найдёт Python 3.8+ (если его нет — предложит установить), запросит
права root и откроет меню. Дальше: **[5]** проверить требования → **[1]**
установить среду → **[2]** запустить обход.

Файл — одновременно сценарий оболочки и программа на Python: начало исполняет
`sh`, остальное — Python. Запускать через `sh` можно и без бита исполнения,
поэтому `chmod +x` не обязателен. Двойной щелчок в файловом менеджере открывает
терминал (для этого бит исполнения нужен).

### Windows

Нужен один файл — любой из двух, второй рядом не требуется. Оба лежат на
странице [релиза](https://github.com/HikariRisser/Zapret2Scrpt/releases/latest):

- **`Zapret2Windows.cmd`** — запуск двойным щелчком. Это самый простой способ.
- **`Zapret2Windows.ps1`** — правой кнопкой → «Выполнить с помощью PowerShell»
  либо `powershell -ExecutionPolicy Bypass -File .\Zapret2Windows.ps1`.

Оба файла — один и тот же скрипт. Права администратора он запрашивает сам.
Дальше: **[5]** проверить требования → **[1]** установить среду → **[2]**
запустить обход. При первом запуске обхода один раз выполняется проверка DNS
(до минуты).

Сборка zapret2 скачивается с GitHub при установке.

## Как работает обход

Перехват системный: под него попадает трафик всех приложений, а не только
браузера. Никакого TLS-MITM, корневых сертификатов и настроек в браузере.

**Только начало соединения.** В `nfqws2`/`winws2` уходят первые пакеты
соединения (Linux: 20 исходящих и 10 входящих TCP, 5 и 3 UDP; Windows: только
исходящие TCP 80/443 и UDP 443). Остальной трафик, включая видео, идёт мимо —
поэтому скорость не падает.

**Профили.**

| Трафик | Что делается |
|---|---|
| HTTP | `fake` + `multisplit` |
| TLS, домены из списков | автоперебор четырёх стратегий (`circular`) отдельно для каждого домена: при двух сбоях домен переключается на следующую стратегию; зависшее соединение сразу обрывается, чтобы программа переподключилась (пункт [12], по умолчанию включено) |
| TLS, подсети крупных хостингов | фейковый ClientHello с «белым» SNI против обрыва после ~16 КБ |
| QUIC | `fake` на `quic_initial` |
| Голос Discord, STUN, WireGuard | `fake` на `discord_ip_discovery`, `stun`, рукопожатие WireGuard |

**Списки доменов.** Стартовый список — 86 доменов (YouTube, Discord,
Meta/WhatsApp, X, Telegram, Twitch, торрент-трекеры, LinkedIn, Proton, Signal и
другие). Autohostlist zapret2 сам дописывает домены, на которых видит
ретрансмиссии или сброс соединения. При обновлении среды (пункт [1]) новые
домены дописываются, ручные правки и выученный список сохраняются. Список
подсетей хостингов тоже можно править; пустой список отключает профиль.

**IPv6** на Linux перехватывается наравне с IPv4.

## DNS через DoH

Обход DPI бесполезен, если провайдер подменяет DNS и сайт вообще не получает
адрес. Пункт **[7]** разрешает такие домены через DoH (Cloudflare, Google,
Quad9) и записывает результат в `hosts` размеченным блоком, который полностью
убирается при удалении.

- В `hosts` попадают только домены, для которых системный DNS отдаёт нерабочий
  адрес. Если системный DNS исправен, запись не делается.
- Адрес перед записью проверяется: собираются ответы всех провайдеров, цели
  CNAME и адреса родительского домена, каждый кандидат проверяется соединением
  на порт 443. Нерабочий адрес не записывается; если рабочего нет, домен
  остаётся системному DNS.
- Домены из списка туннеля в `hosts` не пишутся — иначе они шли бы мимо туннеля.

Обновлять DoH лучше при запущенном обходе.

### Откуда взять сервер

**Proton VPN Free** — бесплатный тариф без лимита трафика. На
[account.protonvpn.com](https://account.protonvpn.com) в разделе Downloads →
WireGuard configuration создайте конфиг для бесплатного сервера и укажите
скрипту путь к файлу `.conf`. Можно добавить несколько файлов.

**Свой сервер** — ссылка, путь к файлу или адрес подписки:

| Формат | Что принимается |
|---|---|
| WireGuard | файл `.conf`, ссылка `wireguard://` |
| VLESS | `vless://` — TCP, Reality, XTLS Vision, WebSocket, gRPC, HTTP, HTTPUpgrade, XHTTP |
| VMess | `vmess://` (base64 с JSON и запись с параметрами) |
| Trojan | `trojan://` |
| Shadowsocks | `ss://` (SIP002, старая запись, Shadowsocks 2022, плагины obfs и v2ray-plugin) |
| Hysteria | `hysteria2://`, `hy2://`, `hysteria://` |
| TUIC | `tuic://` |
| AnyTLS | `anytls://` |
| SOCKS | `socks5://`, `socks4://` |
| Несколько серверов | список ссылок в файле, подписка по адресу `https://…` или в base64 (берутся первые 40) |
| JSON sing-box | один outbound/endpoint или целый конфиг |
| JSON Xray | один outbound или целый конфиг |

Не поддерживается: AmneziaWG.

**Два движка.** TUN, DNS и почти все протоколы обслуживает sing-box. Транспорт
XHTTP и конфиги Xray он не умеет, поэтому для таких профилей дополнительно
скачивается [xray-core](https://github.com/XTLS/Xray-core): он работает
локальным прокси, в который sing-box отправляет трафик. Для остальных профилей
xray-core не скачивается и не запускается. Каждый профиль до сохранения
проверяется своим движком (`sing-box check` или `xray run -test`).

### Как устроено

- sing-box создаёт TUN-адаптер, но направляет в него **только диапазон FakeIP**
  (`10.249.0.0/16`) и **подсети Telegram** ([официальный список](https://core.telegram.org/resources/cidr.txt)).
  Весь остальной трафик идёт мимо sing-box, через zapret.
- Приложение Telegram подключается к серверам по IP, без DNS, поэтому при
  включённом туннеле оно всегда идёт через него. Без туннеля приложение
  Telegram не работает: zapret его трафик не обрабатывает.
- DNS-запросы доменов из списка туннеля система отправляет в sing-box
  (Linux — маршрутные домены systemd-resolved, Windows — правило NRPT). Они
  получают FakeIP и уходят на сервер. Остальной DNS не меняется.
- Настоящий адрес такого домена ищется через сам туннель.
- zapret не трогает трафик, идущий в туннель, и соединение с самим сервером;
  рукопожатие WireGuard он маскирует.
- Адреса TUN, диапазон FakeIP и таблица маршрутов свои, чтобы не конфликтовать
  с другими клиентами на sing-box (Throne, Hiddify, NekoBox).

### Выбор профиля

**Автоматически** (пункт [5]). Каждый профиль запускается на пробу: запрос
`cdn-cgi/trace` показывает страну выхода, измеряется задержка, затем через
профиль открываются сайты из списка региональных ограничений. Порядок выбора:
больше открывшихся сайтов → зарубежный выход → меньшая задержка. Если активный
профиль перестал отвечать, проверяются остальные.

**Региональные ограничения.** Список сайтов (по умолчанию claude.ai,
chatgpt.com, gemini.google.com) можно править. Результат по каждому сайту:
открывается; отвечает, но требует проверку браузера; отказ по региону (код 451,
перенаправление или страница с таким текстом); отказ 403; нет ответа. Пункт
[10] проверяет эти сайты через активный профиль. Если сайт отвечает только
«проверкой браузера», отказ по региону за ней не виден — такой ответ считается
«пускает».

**Вручную** (пункт [4]). Список профилей с результатами последней проверки;
выбранный по номеру профиль закрепляется, и автовыбор его не сменит. Снять
закрепление — ответ `a` там же или пункт [5].

### Какие сайты идут в туннель

Пункт [6] проверяет домены из списков zapret напрямую (дважды, читая 64 КБ,
чтобы поймать обрыв «16 КБ»); не открывшиеся проверяются через туннель и
переносятся в список туннеля. Пункт [7] добавляет домен вручную. Пункт [8]
проверяет сайты из списка так, как их видит браузер. Список можно править в
текстовом редакторе.

### Трансляции Discord

Трансляции (Go Live) и всё больше голосовых каналов Discord работают через
медиасерверы в сети Cloudflare (`104.29.0.0/16`). Discord шлёт на них UDP по
адресу из сигнального соединения, без DNS, поэтому список доменов туннеля их
не касается. У части провайдеров UDP к этим серверам обрезается примерно через
секунду после начала соединения: предпросмотр трансляции виден, но зрители не
могут подключиться, а чужие трансляции не открываются. zapret это не исправляет.

Пункт [6] после проверки сайтов проверяет и это: отправляет медиасерверу
Discord пакет определения IP (сервер отвечает на него без входа в аккаунт),
затем ~3 секунды потока, затем снова пакет определения IP. Итог пишется
отдельной строкой: «работают через zapret» или «zapret не справляется». Во
втором случае UDP к медиасерверам Discord автоматически направляется в туннель
(TCP к этим адресам по-прежнему идёт напрямую через zapret), туннель
перезапускается. Трансляцию после этого нужно начать заново.

Вернуть всё как было: удалить файл `discord-media.on` в каталоге туннеля
(Linux — `/opt/zapret2/tunnel/`, Windows —
`C:\Windows\System32\Zapret2Windows\tunnel\`) и перезапустить туннель.

### Внешний список сайтов с региональными ограничениями

Сайты, которые сами не пускают из России (claude.ai, chatgpt.com, spotify.com и
подобные), проверкой не найти: соединение с ними проходит, отказ приходит уже
от сайта. Поэтому при включении туннеля скачивается готовый список таких
сайтов — раздел GeoBlock проекта
[itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains), около
500 доменов, — и все они идут через туннель.

- Список обновляется раз в сутки: на Linux — таймером systemd
  `zapret2win-geolist.timer`, на Windows — задачей планировщика
  `Zapret2WindowsGeoList`. Кроме того, список старше суток обновляется при
  каждом запуске туннеля. Обновить сразу — пункт [11].
- Домены, убранные из списка его авторами, перестают идти в туннель.
- Свой список туннеля не меняется: внешний хранится в отдельном файле, править
  его вручную бесполезно — он перезаписывается.
- Если список не скачался, туннель работает с прежней копией. Если прямая
  загрузка не удалась, а туннель работает, список скачивается через него.
- Пункт [12] выключает внешний список: в туннель идут только свои сайты.
- Весь трафик этих сайтов идёт через сервер туннеля. На Proton VPN Free видео и
  музыка из списка могут работать медленно — тогда выключите список и добавьте
  нужные сайты вручную.

### Браузер и DNS

Туннель работает через системный DNS. Браузер со своим «DNS через HTTPS» узнаёт
адреса сайтов мимо него и идёт на сайт напрямую.

- Пока туннель работает, Firefox получает штатный сигнал отключить встроенный
  DoH (домен `use-application-dns.net`). Сигнал действует, если DoH включён по
  умолчанию, а не вручную.
- Если DoH включён вручную, его нужно выключить в настройках браузера. Для
  Firefox проверка сайтов (пункт [8]) предупреждает об этом (Linux).
- Домены из списка туннеля остаются в обработке zapret: если запрос всё же ушёл
  напрямую, zapret служит запасным путём.
- После переноса сайта в туннель браузер нужно перезапустить — он помнит
  прежний адрес.

### Запуск вместе с обходом

Если туннель включён, он запускается следом за zapret в фоне; пока идёт запуск,
меню показывает «запускается...». Остановка обхода останавливает и туннель.
Автозапуск обхода (пункт [3]) запускает и туннель: на Linux служба туннеля
привязана к службе zapret, на Windows задача автозапуска поднимает туннель
после обхода. Причина сбоя остаётся в меню туннеля («Последняя ошибка»).

### Ограничения туннеля

- Proton VPN в России блокируют: подключение может не пройти даже с маскировкой
  zapret. Тогда нужен свой сервер с протоколом, устойчивым к DPI (VLESS +
  Reality).
- Ключи и пароли профилей хранятся в `tunnel/profiles.json`. На Linux файл
  доступен только root (права 600). На Windows его могут прочитать все
  пользователи компьютера ([SECURITY.md](SECURITY.md), F-17). В отчёт
  (`report`) попадают только тип и адрес сервера.
- На Linux нужны systemd и systemd-resolved.

| Туннель: обновить внешний список | `tunnel-geolist` | `TunnelGeoList` |
| Туннель: распределить сайты | `tunnel-routes` | `TunnelRoutes` |
| Туннель: проверить сайты | `tunnel-test` | `TunnelTest` |
| Туннель: показать профили | `tunnel-list` | `TunnelList` |

Linux: `--yes` отвечает «да» на вопросы, `--help` показывает справку. Windows:
`-Force` отключает подтверждения при удалении и обновлении.

## Требования

При первом запуске скрипт сам проверяет зависимости и предлагает установить
отсутствующие (пункты [5] и [6]).

### Linux

| Требование | Значение |
|---|---|
| Ядро | с NFQUEUE (модуль `nfnetlink_queue` загружается сам) |
| Архитектура | x86_64, aarch64, armv7, mips, riscv64 |
| Python | 3.8+, только стандартная библиотека |
| Права | root (скрипт запрашивает сам) |
| Файрвол | nftables (предпочтительно) или iptables |
| systemd | для автозапуска и туннеля |
| systemd-resolved | для туннеля |
| Интернет | при установке: zapret2 (~9,5 МБ); при включении туннеля — sing-box и внешний список сайтов; для профилей с XHTTP и конфигов Xray — xray-core |

### Windows

| Требование | Значение |
|---|---|
| ОС | Windows 10 или 11, x64 |
| PowerShell | Windows PowerShell 5.1 (встроен); PowerShell 7 не подходит |
| .NET Framework | 4.x (устанавливается автоматически) |
| Права | администратор |
| Место | около 100 МБ |
| Кодировка | `.ps1` — UTF-8 с BOM (при скачивании с GitHub сохраняется сама); для `.cmd` кодировка не важна |

Автоматически устанавливаются .NET Framework 4.x, поддержка TLS 1.2 и сборка
zapret2. Нельзя установить автоматически: PowerShell 5.1, права администратора,
64-битную Windows.

Что учесть на Windows:

- **Антивирус.** WinDivert часто определяется как hacktool. Добавьте каталог
  проекта и `winws2.exe` в исключения, иначе драйвер не загрузится.
- **Конфликты.** Известны конфликты WinDivert с Hyper-V, WSL2, VirtualBox,
  сторонними VPN-клиентами и фаерволами.
- **Один экземпляр.** WinDivert не даёт открыть второй фильтр с тем же
  выражением.

## Если что-то не работает

**Linux.** Выполните `sh zapret2-linux.sh report` — в `/tmp` появится файл с
состоянием системы, правилами перехвата, журналами обхода и туннеля. Ключей и
паролей в нём нет.

| Симптом | Что проверить |
|---|---|
| Обход запущен, сайты не открываются | пункт [4]; обновить DoH (пункт [7]) при запущенном обходе |
| `nfqws2` не запускается | `systemctl status zapret2win`, `dmesg`, пункт [5] |
| Сайт из туннеля не открывается в браузере | пункт [8] меню туннеля; раздел «Браузер и DNS» |
| Туннель не запускается | «Последняя ошибка» в меню туннеля, `journalctl -u zapret2win-tunnel` |
| Ни один профиль не отвечает | сервер недоступен или его протокол блокируется; попробуйте при запущенном обходе |

**Windows.**

| Симптом | Причина | Решение |
|---|---|---|
| `.ps1`: окно мигает и закрывается, в тексте «кракозябры» | у `.ps1` потерян BOM (файл пересохранён или скопирован как текст) | скачать файл заново или использовать `Zapret2Windows.cmd` |
| Окно мигает и закрывается | PowerShell старше 5.1 | установить Windows Management Framework 5.1 |
| Автозапуск не срабатывает | задача создана версией до 1.8.0 (не запускалась от батареи) | выключить и снова включить автозапуск (пункт [3]) |
| `windivert: error opening filter: Access is denied` | нет прав или блокирует антивирус | запустить от администратора, добавить исключение |
| `Не найден исходный релиз zapret2` | нет сборки и нет интернета | скачать релиз вручную в `zapret2-v1.0.6\` |

При ошибке окно не закрывается, пока не нажата Enter. Журналы туннеля — в
`logs\sing-box*.log`.

## Обновление и релизы

**Релизы.** Готовые файлы для скачивания — на странице
[Releases](https://github.com/HikariRisser/Zapret2Scrpt/releases): к каждому
релизу приложены `zapret2-linux.sh`, `Zapret2Windows.cmd` и
`Zapret2Windows.ps1`, в описании — что изменилось и контрольные суммы SHA-256.

Релизы выпускаются автоматически сценарием GitHub Actions
(`.github/workflows/release.yml`): при слиянии в ветку `main`, если в
`zapret2-linux.sh` стоит версия, для которой релиза ещё нет, и есть описание
`release-notes/<версия>.md`. Перед выпуском сценарий проверяет, что
Linux-скрипт компилируется, а `Zapret2Windows.cmd` соответствует
`Zapret2Windows.ps1`.

**Обновление скрипта.** Пункт **[9]** скачивает свежую версию скрипта из ветки `main` этого
репозитория, сравнивает версии и предлагает замену. Перед записью создаётся
резервная копия (`*.bak`), новый файл проверяется на синтаксис; при ошибке
копия восстанавливается. Если в репозитории версия старее или без маркера
версии, скрипт предупреждает об откате и спрашивает подтверждение.

Обновляется только сам скрипт. Среду zapret2 и списки обновляет пункт [1];
после обновления скрипта конфигурация обхода переписывается сама при следующем
запуске.

**Переход с версий до 1.7.0 на Linux.** Раньше Linux-версия состояла из двух
файлов (`zapret2-linux.sh` и `zapret2-linux.py`). Теперь достаточно скачать
новый `zapret2-linux.sh`, старый `zapret2-linux.py` можно удалить. Файл
`zapret2-linux.py` в репозитории — переходный: он нужен только пункту
«Обновить скрипт» старых версий и сам заменяет себя новым `zapret2-linux.sh`.
Скачивать его вручную не нужно.

## Безопасность

Полный разбор — в [SECURITY.md](SECURITY.md) (аудит версии 1.8.0). Главное:

- **Рабочие файлы** (Lua, списки, фильтры, драйвер, sing-box, xray-core) лежат
  в каталогах, куда пишет только администратор: `C:\Windows\System32\Zapret2Windows`
  и `/opt/zapret2`. TLS не расшифровывается, корневые сертификаты не
  ставятся.
- **Windows: с версии 1.8.4 задачи планировщика запускают защищённую копию
  скрипта из `C:\Windows\System32\Zapret2Windows\`**, а не файл из рабочей
  папки (F-05 закрыта). Копия обновляется при установке, при включении
  автозапуска и при обновлении скрипта. Пока после обновления не выполнена
  установка (пункт [1]) или не переключён автозапуск (пункт [3]), задача
  может указывать на прежнее место: до этого держите скрипт в каталоге, куда
  обычный пользователь писать не может. На Linux службы и таймер запускают
  только файлы из `/opt/zapret2`.
- **Windows: ключи профилей туннеля** с версии 1.8.4 читаемы только
  SYSTEM и Администраторами (F-17 закрыта).
- **Загрузки** с версии 1.8.4 сверяются с SHA-256 (релиз zapret2, sing-box,
  xray-core; версия xray закреплена). Самообновление по-прежнему берёт
  скрипт из ветки `main` без подписи (F-18).
- **Туннель:** оператор сервера видит адреса и имена сайтов, которые идут в
  туннель; подписка — это доверие её автору (F-20). Внешний список решает,
  какие сайты идут в туннель, но выполнить код или увести трафик на чужой
  сервер не может (F-19).

## Ограничения

- Обход DPI — не VPN. Он не помогает, когда заблокированы сами адреса сервера
  или сервис отказывает по региону; для этого есть туннель.
- HTTP/2 не переписывается: штатный `tls_mod` zapret2 не умеет менять ALPN.
- Стратегия, выбранная автоперебором, держится в памяти до перезапуска обхода.
- Диагностика разделяет доступность TCP, результат HTTP и ошибки запуска. Код
  `200` на один запрос не доказывает, что работают все приложения, WebSocket,
  QUIC или голосовые каналы.
- Полный голосовой сеанс Discord без авторизованного клиента проверить нельзя;
  проверены сигнализация, API, UDP-путь и срабатывание профиля.

## Что проверено

**Linux, на машине пользователя (Ubuntu 26.10, nftables):** обход работает
(YouTube, Discord); туннель запускается с профилями VLESS + Reality из
подписки; автовыбор профиля с проверкой региональных ограничений; DNS доменов
туннеля через systemd-resolved.

**Linux, в тестовой среде:**

- все форматы серверов разбираются и проходят проверку настоящими sing-box
  1.14.4 и xray-core;
- цепочка sing-box → xray-core → VLESS + XHTTP → сервер работает на localhost;
- параметры обхода проходят `nfqws2 --dry-run`;
- запуск одним файлом через `sh`, `dash`, `bash` и самообновление;
- внешний список: разбор, объединение со своим списком, обновление по
  возрасту, поведение при сбое загрузки (на подставных данных).

**Выпуск:** релизы создаются сценарием GitHub Actions автоматически.

**Windows, в CI (с 1.8.4):** скрипт разбирается PowerShell 5.1 (целевой
средой), проверяется PSScriptAnalyzer, все определения загружаются без
ошибок, смок-действия чтения выполняются на настоящем Windows-раннере.

**Не проверено:**

- Windows-версия ни разу не запускалась на настоящей машине с Windows
  (туннель, запуск одним файлом, ускорение);
- автозапуск туннеля при загрузке Linux;
- загрузка внешнего списка из сети и его суточное обновление таймером;
- распознавание отказа по региону на настоящих ответах сайтов;
- отключение DoH в Firefox по сигналу.

## Структура проекта

```
zapret2-linux.sh      Linux: контроллер одним файлом (sh + Python)
zapret2-linux.py      переходный файл для обновления с версий до 1.7.0
Zapret2Windows.ps1    Windows: контроллер
Zapret2Windows.cmd    Windows: тот же контроллер для запуска двойным щелчком (собирается из .ps1)
README.md             документация (английская)
README.ru.md          документация (русская)
SECURITY.md           аудит безопасности
LICENSE               MIT
release-notes/        описания релизов (<версия>.md)
.github/workflows/    release.yml — автоматический выпуск релиза
tools/                build-cmd.py (сборка .cmd из .ps1) и необязательная диагностика для Node.js
```

`Zapret2Windows.cmd` не правится вручную: он собирается из `Zapret2Windows.ps1`
командой `python3 tools/build-cmd.py` (`--check` проверяет соответствие).

`tools/probe-h2.js` сравнивает HTTP/2 и HTTP/1.1 для заданных доменов,
`tools/probe-voice.js` проверяет сигнализацию и UDP-путь голоса Discord:

```bash
node tools/probe-h2.js discord.com rutracker.org www.youtube.com
node tools/probe-voice.js
```

Сборка zapret2, sing-box и xray-core в репозитории не хранятся — они
скачиваются с официальных релизов при установке. На Windows сборку zapret2
можно положить вручную в `zapret2-v1.0.6\`; `winws2.exe`, файлы WinDivert и
библиотеки Lua должны быть из одного релиза.
