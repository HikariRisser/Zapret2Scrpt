# Zapret2 Windows / Linux — системный контроллер

[English version](README.md) · [Аудит безопасности](SECURITY.md) · [Лицензия](LICENSE)

Контроллер для `bol-van/zapret2` (релиз v1.0.6): системная
DPI-десинхронизация для всех приложений, обход DNS-блокировок через DoH,
автообучение доменов и полное удаление из системы.

Две реализации с одинаковым набором возможностей:

| Платформа | Файл | Движок перехвата |
|---|---|---|
| Windows | [`Zapret2Windows.ps1`](Zapret2Windows.ps1) | `winws2` + WinDivert |
| Linux | [`zapret2-linux.py`](zapret2-linux.py) | `nfqws2` + nftables/iptables |

Интерфейс скриптов — на русском языке.

## WARP для сайтов, которые не открывает zapret (1.3.0)

Пункт меню **[11]**. zapret обходит DPI, но не помогает, когда адрес сервера
заблокирован целиком или соединение рвётся вне его досягаемости. Для таких
сайтов скрипт поднимает **Cloudflare WARP** через
[sing-box](https://github.com/SagerNet/sing-box) (v1.14.4, скачивается с GitHub
при первом включении).

**Как устроено — и почему не страдает скорость:**

- sing-box создаёт TUN-адаптер, но направляет в него **только диапазон FakeIP**
  (`198.18.0.0/15`). Весь остальной трафик идёт мимо sing-box, напрямую, через
  zapret.
- DNS-запросы системы обрабатывает sing-box: домены из списка WARP получают
  FakeIP и уходят в туннель WireGuard к Cloudflare, остальные разрешаются
  обычным системным DNS (записи DoH из `hosts` продолжают работать).
- Настоящий адрес домена из списка WARP разрешается через `1.1.1.1` **внутри
  туннеля** — подмена DNS провайдером на эти домены не действует.
- zapret эти домены не трогает (они добавлены в исключения всех профилей), а
  рукопожатие самого WireGuard, наоборот, маскирует фейками (профиль [5]).

**Автоматический выбор узла Cloudflare.** Для подсетей WARP
(`162.159.192–195.x`, `188.114.96–99.x`) и официальных портов (2408, 500,
1701, 4500) поднимается пробный туннель, через него делается запрос к
`1.1.1.1/cdn-cgi/trace` (ответ `warp=on` подтверждает работу), задержка
замеряется по 2-му и 3-му запросу. Выбирается самый быстрый узел. При каждом
запуске узел проверяется заново и, если не отвечает, заменяется.

**Автоматическое распределение «zapret или WARP».** Пункт WARP → **[3]**
(запускается и сам при включении WARP) проверяет все домены из списков zapret:
скачивает начало главной страницы напрямую (через zapret). Не открывшиеся —
включая обрыв на «16 КБ» — проверяются через WARP, и те, что там работают,
переносятся в `lists\warp.txt` (Linux: `ipset/zapret2win-hosts-warp.txt`).
Список можно править вручную, домены совпадают с поддоменами.

| | Windows | Linux |
|---|---|---|
| Включить | меню [11] → [1] или `-Action WarpOn` | `--action warp-on` |
| Выключить | `-Action WarpOff` | `--action warp-off` |
| Подобрать узел | `-Action WarpScan` | `--action warp-scan` |
| Распределить сайты | `-Action WarpRoutes` | `--action warp-routes` |
| Импорт конфига | `-Action WarpImport -WarpConfig wgcf.conf` | `--action warp-import --warp-config wgcf.conf` |
| Процесс | `sing-box.exe`, запускается вместе с обходом | служба `zapret2win-warp` (нужен systemd) |

**Запуск вместе с обходом.** Если WARP включён, он запускается следом за
zapret автоматически, в фоне: сам обход стартует сразу, а проверка узла
Cloudflare (и при необходимости подбор нового) идёт отдельно. Пока это
происходит, меню показывает «WARP: запускается...»; ход запуска — в
`logs\warp-start.log` (Linux: `/opt/zapret2/warp/start.log`). Остановка
обхода останавливает и WARP.

**Если WARP включён, но не запускается**, причина показывается сразу и
остаётся в меню WARP («Последняя ошибка»). Журналы: Windows —
`C:\Windows\System32\Zapret2Windows\logs\sing-box*.log`, Linux —
`journalctl -u zapret2win-warp`. «Ни один узел WARP не ответил» означает,
что WireGuard к Cloudflare у провайдера не проходит; «sing-box завершился» —
проблема самого sing-box (адаптер TUN, права), её текст будет в журнале.

**Регистрация.** Скрипт регистрирует бесплатное устройство WARP через API
Cloudflare так же, как приложение 1.1.1.1 (протокол взят из
[wgcf](https://github.com/ViRb3/wgcf)). Если регистрация не проходит
(блокировка API, изменение протокола), импортируйте готовый WireGuard-конфиг
WARP из wgcf или WarpGen — пункт WARP → [5].

**Ограничения.**

- Выход WARP часто находится в российских узлах Cloudflare, поэтому
  геоблокировки самих сервисов (ChatGPT, Spotify) WARP обходит ненадёжно.
- Если WireGuard к Cloudflare у провайдера заблокирован полностью, подбор
  узла не найдёт ни одного рабочего — помогает запущенный zapret.
- На Linux перехват DNS надёжен при `systemd-resolved` или DNS-сервере в
  локальной сети; если в `/etc/resolv.conf` указан внешний DNS, домены WARP
  не будут перехвачены.

**Проверено в тестовой среде:** конфиги (рабочий, пробный и вариант для
Windows) проходят `sing-box check` на настоящем sing-box 1.14.4; запуск
sing-box с этим конфигом выдаёт FakeIP доменам из списка (и их поддоменам) и
не трогает остальные; архив sing-box скачивается и распаковывается.
**Не проверено:** регистрация WARP (API недоступен из тестовой среды),
WireGuard-туннель и подбор узлов (нет UDP наружу), Windows-часть на реальной
Windows (PowerShell-парсер недоступен).

## Что нового в 1.2.0: скорость и охват

**Скорость.**

- Windows: убран перехват **всего входящего** трафика 80/443 и UDP 443
  (`--wf-tcp-in`, `--wf-udp-in`) и всех пустых ACK (`--wf-tcp-empty`). Раньше
  каждый скачиваемый пакет — включая видео YouTube по QUIC — проходил через
  `winws2` в пользовательском режиме. По документации zapret2 одни только
  пустые ACK дают до ~50% лишней нагрузки на CPU при активных загрузках.
  Стратегиям входящие данные не нужны, а SYN+ACK/FIN/RST и HTTP-редиректы
  фильтр-конструктор winws2 перехватывает сам.
- DoH-пиннинг больше не пишет в `hosts` домены, для которых **системный DNS
  отдаёт рабочий адрес** (проверяется TLS-сертификат). Раньше в `hosts`
  попадали и YouTube/Discord/Cloudflare — с адресом, выбранным чужим
  резолвером: CDN отдавал дальний узел, а со временем адрес устаревал.
  Теперь пиннинг только там, где DNS действительно подменён.
- Linux: в `config` не было `NFQWS2_TCP_PKT_OUT/IN` и `NFQWS2_UDP_PKT_OUT/IN`,
  и init-скрипт zapret2 **не создавал правила перехвата вовсе**. Теперь
  заданы официальные значения (20/10 и 5/3): в `nfqws2` уходят только первые
  пакеты соединения.

**Меньше сайтов, которым нужен VPN.**

- **Автоперебор стратегий TLS.** Для доменов из списков работает оркестратор
  `circular`: если текущая стратегия не проходит (2 сбоя — ретрансмиссии
  ClientHello или RST от DPI), домен 2-го уровня переключается на следующую.
  Стратегия 1 — прежняя (`fake + multidisorder`), дальше: фейк с белым SNI +
  `multisplit`, `hostfakesplit`, `multisplit` с `seqovl` без fooling.
  Выбор держится в памяти до перезапуска обхода.
- **Блокировка «16 КБ».** ТСПУ обрывает соединения к крупным хостингам после
  ~16 КБ, если домен не в его белом списке, — поэтому раньше «вдруг» не
  догружались сайты, которых нет в наших списках. Новый профиль ловит такие
  соединения по подсетям хостинга (`lists\ipset-hosting.txt`) и шлёт фейковый
  ClientHello с белым SNI (`$script:WhiteSni`, по умолчанию `www.google.com`).
  Файл подсетей можно дополнять; если удалить из него все строки, профиль
  отключится.
- **Список доменов расширен** с 37 до 86 (полные наборы YouTube, Discord,
  Meta/WhatsApp, X, Telegram, Twitch, торрент-трекеры, LinkedIn, Proton,
  Signal, Viber, Roblox и др.). При обновлении среды (пункт **[1]**) новые
  домены **дописываются** в существующие списки — ручные правки и выученный
  autohostlist сохраняются.
- **IPv6 на Linux** теперь тоже перехватывается (`DISABLE_IPV6=0`), иначе
  браузер уходил на AAAA-адрес мимо обхода.

**Что по-прежнему не лечится:** геоблокировки со стороны самих сервисов
(ChatGPT, Spotify, Notion и т.п. — это не DPI) и полная блокировка IP-адресов.

Чтобы применить изменения на уже установленной системе: обновите скрипт
(пункт **[9]**), затем выполните установку (пункт **[1]**) — она перепишет
конфиг запуска и дополнит списки — и запустите обход. Обновление DoH
(пункт **[7]**) лучше делать при запущенном обходе.

## Linux-версия

```bash
./zapret2-linux.sh                       # меню (лаунчер сам запросит root)
./zapret2-linux.sh install               # любое действие: install, start, warp-on...
./zapret2-linux.sh check                 # проверка требований без root
```

Лаунчер `zapret2-linux.sh` находит Python 3.8+ (если его нет — предлагает
установить), сам запрашивает права (sudo, doas, pkexec или su), при запуске
двойным щелчком открывает терминал и не закрывает окно при ошибке. Если
после скачивания ZIP файл не исполняемый: `chmod +x zapret2-linux.sh`.

Напрямую через Python:

```bash
sudo python3 zapret2-linux.py            # интерактивное меню
sudo python3 zapret2-linux.py -a install # установить среду
python3 zapret2-linux.py -a check        # проверить требования
python3 zapret2-linux.py --help
```

Пункты меню те же, что в Windows-версии (10 пунктов, переключатели
запуска и автозапуска).

### Требования к Linux-машине

| Требование | Значение | Почему |
|---|---|---|
| **ОС** | Linux, ядро с NFQUEUE | перехват идёт через `nfqws2` |
| **Архитектура** | x86_64, aarch64, armv7, mips, riscv64 | берётся готовая сборка zapret2 |
| **Python** | 3.8+ | скрипт написан на Python, внешних пакетов нет |
| **Права** | root (через `sudo`) | правила файрвола, `/opt`, `/etc/hosts`, systemd |
| **Файрвол** | `nftables` (предпочтительно) или `iptables` | перенаправление в NFQUEUE |
| **Модуль ядра** | `nfnetlink_queue` | загружается автоматически |
| **systemd** | для автозапуска (необязательно) | служба `zapret2win` |
| **Интернет** | при первой установке | релиз zapret2 (~9.5 МБ) с GitHub |

Проверить всё сразу: `python3 zapret2-linux.py -a check` или пункт **[5]**.

### Отличия от Windows-версии

| | Windows | Linux |
|---|---|---|
| Перехват | WinDivert (драйвер ядра) | NFQUEUE (`nfqws2` + nftables) |
| Движок | `winws2` напрямую | init-скрипт zapret2 (`/opt/zapret2/init.d/sysv/zapret2`) |
| Расположение | `System32\Zapret2Windows` | `/opt/zapret2` (владелец root) |
| Автозапуск | задача планировщика (SYSTEM) | служба systemd |
| Списки доменов | `lists\*.txt` | `/opt/zapret2/ipset/zapret-hosts-*.txt` |
| Сброс DNS | `ipconfig /flushdns` | `resolvectl flush-caches` / `nscd -i hosts` |

Логика стратегий, профили (HTTP, TLS, QUIC, голос Discord), DoH с проверкой
рабочего IP, обновление скрипта и удаление — идентичны Windows-версии.

### Важно про права из архива

Python-модуль `zipfile` **не восстанавливает** права доступа из архива,
поэтому установщик явно делает исполняемыми все `*.sh`, `nfqws2`, `mdig`,
`ip2net` и `init.d/sysv/zapret2`. Без этого init-скрипт не запустится.

### Статус тестирования Linux-версии

Разработка велась на Windows, поэтому честно о проверенном:

**Проверено локально (Python 3.12):**
- синтаксис (`py_compile`) — без ошибок;
- сравнение версий и извлечение маркера `VERSION`;
- DoH-разрешение со всех провайдеров + проверка рабочего IP
  (`www.instagram.com` → `57.145.12.34`, мёртвый `31.13.72.174` отбрасывается);
- удаление размеченного блока `hosts` (наш и прежней версии проекта);
- генерация `config` и systemd-юнита;
- корректный отказ при запуске не на Linux;
- **1.2.0:** сгенерированные параметры `nfqws2` проходят `nfqws2 --dry-run`
  (бинарник v1.0.6 linux-x86_64), все Lua-функции стратегий загружаются;
  на реальном NFQUEUE по debug-логу `nfqws2` проверены загрузка всех
  профилей, проверка подсетей хостинга и списка исключений. Сам обход
  (отправка фейков) в тестовой среде не проверялся — нет raw-сокетов.

**НЕ проверено (нужен запуск на Linux):**
- фактический старт `nfqws2` через init-скрипт;
- создание правил nftables/iptables и отсутствие петель маршрутизации;
- регистрация и работа службы systemd;
- установка пакетов через `apt`/`dnf`/`pacman`;
- реальный обход DPI на конкретном провайдере.

Первый запуск на целевой машине начните с пункта **[5]** (проверка
требований), затем **[1]** (установка), затем **[2]** (запуск) и **[4]**
(диагностика). Если `nfqws2` не стартует — смотрите вывод
`systemctl status zapret2win` и `dmesg`.

## Требования для запуска

При **первом запуске** скрипт сам проверяет зависимости и предлагает
установить отсутствующие. Вручную: пункт **[11]** (проверка) и
**[12]** (установка) или `-Action Check` / `-Action Deps`.

### Что устанавливается автоматически

| Зависимость | Способ |
|---|---|
| **.NET Framework 4.x** | winget → chocolatey → прямая загрузка официального установщика 4.8 (`/q /norestart`) |
| **TLS 1.2 для .NET** | ключи реестра `SchUseStrongCrypto` + `SCHANNEL\Protocols\TLS 1.2` |
| **Сборка zapret2** | скачивание релиза с GitHub (~9.5 МБ) |
| **Node.js** *(необязательно)* | winget / chocolatey; нужен только для `tools/` |

Перед скачиванием релиза скрипт **включает TLS 1.2**, если он выключен —
иначе загрузка с GitHub на чистой системе падает.

### Что установить автоматически нельзя

| Зависимость | Почему |
|---|---|
| **Windows PowerShell 5.1** | скрипт исполняется им же (курица и яйцо); WMF 5.1 снят с сайта Microsoft — нужен ручной шаг |
| **Права администратора** | выдаёт пользователь через UAC |
| **64-битная Windows** | переустановка ОС |

### Обязательно

| Требование | Значение | Почему |
|---|---|---|
| **ОС** | Windows 10 или 11, **x64** | WinDivert — подписанный драйвер ядра, современные подписи только x64 |
| **PowerShell** | **Windows PowerShell 5.1** (встроен) | `.cmd` вызывает `powershell.exe`; PowerShell 7 сам по себе не подходит |
| **.NET Framework** | 4.x | нужен PowerShell и WinDivert-обвязке |
| **Права** | **администратор** | драйвер ядра, `System32`, `hosts`, задача планировщика |
| **Интернет** | при первой установке | сборка zapret2 скачивается с GitHub, нужен TLS 1.2 |
| **Место** | ~100 МБ | сборка, среда, журналы |
| **Кодировка `.ps1`** | **UTF-8 с BOM** | без BOM PowerShell 5.1 читает файл как ANSI и скрипт падает |

### Важно учесть

- **Антивирус и EDR.** WinDivert часто определяется как hacktool. Добавьте
  каталог проекта и `winws2.exe` в исключения, иначе драйвер не загрузится
  (ошибка `windivert: error opening filter: Access is denied`).
- **Конфликтующее ПО.** Документированы конфликты WinDivert с Hyper-V, WSL2,
  VirtualBox, сторонними VPN-клиентами и фаерволами — вплоть до BSOD.
- **Путь без кириллицы** — рекомендация: часть внешних утилит её не переваривает.
- **Не запускайте два экземпляра.** WinDivert не даёт открыть второй фильтр
  с тем же выражением.

### Необязательно

- **Node.js** — только для диагностики в `tools/` (`probe-h2.js`, `probe-voice.js`).
- **git** — только для клонирования репозитория; можно скачать ZIP-архивом.

## Если скрипт закрывается мгновенно

| Симптом | Причина | Решение |
|---|---|---|
| Окно мигает и закрывается | у `.ps1` нет **BOM** | сохранить как «UTF-8 с BOM» или скачать заново |
| Окно мигает и закрывается | PowerShell старше 5.1 | установить Windows Management Framework 5.1 |
| Окно мигает и закрывается | файл `.ps1` не рядом с `.cmd` | положить оба файла в одну папку |
| Появилось `[ERROR] Script exited with code 1` | смотрите текст ошибки выше | окно теперь **не** закрывается — прочитайте сообщение |
| `windivert: error opening filter: Access is denied` | нет прав или блокирует антивирус | запустить от администратора, добавить исключение |
| `Не найден исходный релиз zapret2` | нет сборки и нет интернета | скачать релиз вручную в `zapret2-v1.0.6/` |

Лаунчер `Zapret2Windows.cmd` специально проверяет кодировку файла до запуска и
**держит окно открытым** при любой ошибке — молчаливого закрытия больше нет.

## Быстрый старт

1. Клонируйте репозиторий (или распакуйте ZIP).
2. Запустите `Zapret2Windows.cmd` **от имени администратора**.
3. Выберите пункт **[5]** — проверка требований.
4. Выберите пункт **[1]** — установка. Сборка zapret2 скачается с GitHub
   автоматически, если её нет рядом со скриптом.
5. Выберите пункт **[2]** — запуск системного обхода.

Пункты меню:

| Пункт | Действие |
|---|---|
| [1] | Установить или обновить среду zapret2 |
| [2] | Запустить / остановить обход *(переключатель)* |
| [3] | Автозапуск при входе: включить / выключить *(переключатель)* |
| [4] | Диагностика ресурсов |
| [5] | Проверить требования |
| [6] | Установить отсутствующие зависимости |
| [7] | Обновить DNS через DoH |
| [8] | Выученные домены и журналы |
| [9] | Обновить скрипт |
| [10] | Удалить из системы |
| [11] | WARP для сайтов, которые не открывает zapret |
| [0] | Выход |

Подписи пунктов **[2]** и **[3]** меняются по фактическому состоянию: если
обход запущен, пункт предлагает «Остановить», иначе — «Запустить». Так же
с автозапуском. Отдельного «выключить» больше нет — одно действие на оба
состояния.

## Обновление скрипта (пункт [9])

Источник обновлений:

```
https://github.com/HikariRisser/Zapret2Scrpt
```

Скрипт скачивает `Zapret2Windows.ps1` из ветки `main` (при её отсутствии
пробует `master`), сравнивает версии и предлагает обновление.

Версия хранится в самом скрипте:

```powershell
$script:ScriptVersion='1.3.2'
```

Порядок работы:

1. скачивается удалённая копия, из неё извлекается версия;
2. содержимое сравнивается с локальным (нормализуются переводы строк и BOM);
3. если совпадает — сообщается «уже последняя версия»;
4. если версия новее — предлагается установка;
5. если версия **старее** или в репозитории файл **без маркера версии** —
   выводится предупреждение об откате и запрос подтверждения;
6. перед записью создаётся резервная копия
   `Zapret2Windows.ps1.<дата-время>.bak`;
7. новый файл проверяется парсером PowerShell; при синтаксической ошибке
   автоматически восстанавливается резервная копия;
8. после успешной замены предлагается перезапуск.

Командная строка:

```powershell
.\Zapret2Windows.ps1 -Action Update          # с подтверждениями
.\Zapret2Windows.ps1 -Action Update -Force   # без вопросов
```

**Важно:** обновляется только сам скрипт. Среда zapret2, списки доменов и
задача автозапуска не затрагиваются — для них пункт **[1]**.

Если в репозитории лежит копия без маркера `ScriptVersion`, скрипт считает её
потенциально устаревшей и требует явного подтверждения. Это защита от отката
рабочей версии старой копией.

Установка копирует архитектурно подходящие официальные `winws2`, драйвер и DLL
WinDivert, runtime Cygwin, библиотеки Lua, списки хостов и официальные
фрагменты WinDivert-фильтров в `runtime\winws2` и в защищённый каталог
`C:\Windows\System32\Zapret2Windows`.

Запуск включает системный перехват через WinDivert. Это не браузерный прокси:
под перехват попадает TCP/UDP-трафик **всех** приложений.

Эквиваленты в командной строке:

```powershell
powershell -ExecutionPolicy Bypass -File .\Zapret2Windows.ps1 -Action Install
powershell -ExecutionPolicy Bypass -File .\Zapret2Windows.ps1 -Action Start
powershell -ExecutionPolicy Bypass -File .\Zapret2Windows.ps1 -Action Status
powershell -ExecutionPolicy Bypass -File .\Zapret2Windows.ps1 -Action Diagnose
powershell -ExecutionPolicy Bypass -File .\Zapret2Windows.ps1 -Action DohHosts
powershell -ExecutionPolicy Bypass -File .\Zapret2Windows.ps1 -Action Stop
powershell -ExecutionPolicy Bypass -File .\Zapret2Windows.ps1 -Action Uninstall
```

## Удаление из системы

Пункт меню **[9]** (или `-Action Uninstall`) полностью удаляет проект из
системы за пять шагов:

| Шаг | Что удаляется |
|---|---|
| 1/5 | процесс `winws2` |
| 2/5 | задача планировщика `Zapret2Windows` (автозапуск) |
| 3/5 | служба ядра `WinDivert` |
| 4/5 | защищённый каталог `C:\Windows\System32\Zapret2Windows` |
| 5/5 | размеченный блок в `hosts` (наш и от прежней версии проекта) |

После удаления печатается проверка остатков по каждому компоненту. Команда
идемпотентна — повторный запуск безопасен. Перед правкой `hosts` создаётся
резервная копия `hosts.zapret-backup`.

Полезные варианты:

```powershell
# удалить и рабочий каталог проекта
.\Zapret2Windows.ps1 -Action Purge -IncludeProject

# сохранить копию логов перед удалением
.\Zapret2Windows.ps1 -Action Uninstall -KeepLogs

# без запроса подтверждения
.\Zapret2Windows.ps1 -Action Uninstall -Force
```

**Не затрагивается:** хранилище сертификатов, прочие файлы `System32`,
посторонние записи `hosts`, рабочая папка проекта (если не указан
`-IncludeProject`).

## DNS через DoH

DPI-десинхронизация не помогает, если провайдер **вообще не отдаёт IP**
(DNS-блок): `youtube.com` и `rutracker.org` в такой ситуации просто не
резолвятся. Поэтому контроллер разрешает имена через DoH (Cloudflare, Google,
Quad9) и записывает результат в `hosts` размеченным блоком:

```
# --- Zapret2Windows DoH begin ---
172.67.182.196	rutracker.org
...
# --- Zapret2Windows DoH end ---
```

Запускается автоматически при `Install`, вручную — пункт **[10]** или
`-Action DohHosts`. Учитывайте, что `hosts` сопоставляет точное имя, поэтому
`www`-варианты разрешаются отдельно. Полностью удаляется командой `Uninstall`.

### Проверка рабочего IP (важно)

DoH нередко возвращает **мёртвый edge-адрес** — типично для Meta/Instagram:
`31.13.72.174` не отвечает, тогда как `57.145.12.34` работает. Если записать
первый попавшийся адрес в `hosts`, доступ к сайту **сломается**, хотя до
пиннинга он мог работать. Поэтому адрес перед записью проверяется:

1. A-записи собираются **со всех DoH-провайдеров** (Cloudflare, Google,
   Quad9) — разные узлы CDN отдают разные адреса, среди них бывает живой;
2. добавляются CNAME-цели (`www.instagram.com` →
   `z-p42-instagram.c10r.instagram.com`);
3. для `www.X` добавляются адреса родительского `X`;
4. каждый кандидат проверяется **реальным TCP-соединением на порт 443**;
5. в `hosts` пишется только подтверждённо рабочий адрес.

Если рабочего адреса нет ни одного, домен **не пиннингуется** — он остаётся
системному DNS. Это лучше, чем жёстко прописать мёртвый IP.

В отчёте такие домены видны строкой «Без рабочего IP» (например,
`ytimg.com`, `twimg.com`, `githubassets.com` — они обычно отдаются через
CNAME и работают без отдельной записи).


## Что реализовано

- выбор официального релиза x64/x86 по разрядности Windows;
- перехват WinDivert только **исходящих** пакетов TCP 80/443 и UDP 443
  (входящие SYN+ACK/FIN/RST и HTTP-редиректы winws2 добавляет сам);
- официальные `zapret-lib.lua`, `zapret-antidpi.lua` и `zapret-auto.lua` из того же релиза;
- стратегия для HTTP: `fake + multisplit`;
- стратегия для TLS: **автоперебор 4 стратегий** (`circular`) отдельно для
  каждого домена;
- **профиль для хостингов** (Cloudflare, Hetzner, OVH, AWS CloudFront,
  DigitalOcean) против блокировки «16 КБ» — фейк с белым SNI;
- стратегия для QUIC: `fake` на `quic_initial`;
- **профиль голоса/медиа Discord**: `fake` на `discord_ip_discovery`, `stun`,
  `wireguard_initiation`, `wireguard_cookie` (официальная схема zapret2 из
  `init.d/custom.d.examples.*/50-discord-media`, `50-stun4all`, `50-wg4all`);
- официальные raw-фильтры WinDivert для медиа Discord, STUN и WireGuard;
- статический список хостов плюс автообучаемый autohostlist zapret2;
- **DNS через DoH** для обхода DNS-блокировок (размеченный блок в `hosts`,
  полностью удаляется командой `Uninstall`);
- **полное удаление из системы** (процесс, задача, служба ядра, каталог, hosts);
- логи, отслеживание PID, безопасная остановка, статус, диагностика и
  автозапуск;
- никакого TLS-MITM, никакого корневого сертификата, никакой
  браузер-специфичной настройки.

Runtime стартует с консервативного начального списка. Autohostlist zapret2
выучивает домены, когда детектор сбоев видит ретрансмиссии, RST или
недостаточные ответы. Выученный список хранится здесь:

```text
C:\Windows\System32\Zapret2Windows\lists\autohostlist.txt
```

## Голосовые каналы Discord

Голос использует другой транспорт, чем веб-клиент: UDP-медиапуть плюс
WebSocket-шлюз для сигнализации. Поэтому у контроллера есть отдельный
4-й профиль, который десинхронизирует `discord_ip_discovery`, `stun` и
WireGuard-payload, а в захват WinDivert включены официальные фрагменты для
медиа/UDP.

Проверено на этой машине:

| проверка | результат |
|---|---|
| HTTPS API (`/api/v9/gateway`) | 200 |
| HTTPS API (`/api/v9/voice/regions`) | 401 (доступен; нужен вход в аккаунт) |
| WSS voice-шлюз `gateway.discord.gg` | Hello `op=10`, heartbeat есть |
| UDP STUN binding (Google / Cloudflare) | `0x0101` success, mapped-адрес получен |
| Профиль на `discord_ip_discovery` (debug) | `profile 4 matches` → `fake_4_1 desync` |
| Профиль на `stun` (debug) | `fake_4_1 : payload_type 'stun' satisfy filter` |

Отладочная трассировка синтетического 74-байтного IP-discovery пакета на
порт 50000:

```text
UDP: len=74 : 00 01 00 46 ...
packet contains discord_ip_discovery payload
discovered l7 protocol
desync profile 4 (noname) matches
* lua 'fake_4_1' : payload_type 'discord_ip_discovery' satisfy filter
* lua 'fake_4_1' : desync
```

**Ограничение:** полный голосовой сеанс (вход в канал и двусторонний звук)
нельзя проверить без авторизованного клиента Discord — реальный voice-endpoint
выдаётся только после входа в аккаунт. Проверены все измеримые транспорты:
сигнализация (WSS), API и UDP-медиапуть, плюс факт срабатывания профиля.

## Безопасность

Боевые ресурсы (`Lua`, списки, фильтры и драйвер ядра) размещаются в
`C:\Windows\System32\Zapret2Windows`, где обычные пользователи имеют только
чтение. Это сделано намеренно: рабочая папка проекта может быть доступна на
запись другим пользователям, а `winws2` исполняет Lua внутри процесса с
правами администратора/SYSTEM и доступом к драйверу ядра. Подробный разбор
угроз, что устранено и что осталось — в [SECURITY.md](SECURITY.md).

Перед включением автозапуска перенесите сам скрипт `Zapret2Windows.ps1` в
каталог, недоступный на запись обычным пользователям, — иначе задача от
SYSTEM остаётся вектором эскалации привилегий.

## Важные ограничения

Это системный контроллер DPI-десинхронизации, **а не VPN**. Он справляется с
трафиком, который достижим на уровне IP/TCP, но подвергается вмешательству
DPI. Он не может восстановить маршрут, когда фильтруются все IP-адреса
назначения, и не может превратить локальный SOCKS-прокси в прозрачный
системный туннель. Для полных IP/маршрутизационных блокировок и произвольных
UDP-сервисов нужен внешний системный маршрут: WireGuard, Wintun/TUN или
другой VPN-endpoint.

HTTP/2 намеренно не переписывается. Релиз поддерживает реассемблирование
TLS ClientHello для десинхронизации, но штатный `tls_mod` не умеет менять
ALPN. Небезопасная подмена пакетов через Lua может нарушить TCP
sequence/reassembly и сломать TLS.

Скрипт не обещает, что заработает «всё и всегда»: его диагностика разделяет
доступность TCP, результат HTTP и ошибки запуска WinDivert. Код `200` на один
HTTP-запрос не доказывает, что работают все native-приложения, WebSocket,
QUIC или UDP-медиапотоки.

## Диагностика (tools/)

Необязательные скрипты для Node.js — помогают понять, на каком уровне сбой:

```bash
node tools/probe-h2.js discord.com rutracker.org www.youtube.com
node tools/probe-voice.js
```

`probe-h2.js` сравнивает HTTP/2 и HTTP/1.1 — показывает, ломается ли конкретно
HTTP/2. `probe-voice.js` проверяет сигнализацию (HTTPS API, WSS-шлюз) и
UDP-медиапуть (STUN) для голосовых каналов Discord.
