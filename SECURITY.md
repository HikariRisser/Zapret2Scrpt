# Аудит безопасности Zapret2 Windows / Linux

**Версия:** 1.8.0 (коммит `a42a3da`). **Дата:** 2026-11-15.
**Предыдущий аудит:** 2026-11-03, только Windows (находки F-01…F-15).

> **Статус на 1.8.4:** часть находок этого аудита закрыта. Задачи планировщика
> запускают защищённую копию скрипта из System32 (F-05), загрузки сверяются
> с SHA-256 и версия xray-core закреплена (F-06), каталог туннеля с ключами
> закрыт ACL (F-17). Подробности — `release-notes/1.8.4.md`. Формулировки
> ниже соответствуют версии 1.8.0 и сохранены для истории.

## Как проводился аудит

- **Windows, 2026-11-03:** проверка на работающей системе (Windows 10 22H2):
  ACL каталогов, путь драйвера, конфиг `winws2`, параметры задачи. Отсюда
  находки F-01…F-04.
- **Windows, 2026-11-15:** только чтение кода версии 1.8.0. Скрипт после
  переработки (туннель, запуск одним файлом) ни разу не запускался, ACL
  выведены из наследования прав каталога `System32`, а не проверены на системе.
- **Linux, 2026-11-15:** чтение кода и проверка в тестовой среде (права файлов,
  содержимое юнитов systemd, удаление из системы). Часть поведения
  подтверждена на машине пользователя (Ubuntu 26.10).

В каждой находке указано, на чём она основана.

## Модель угроз

1. **Локальный пользователь без прав администратора** или вредоносная
   программа, работающая от его имени. Цель — получить права администратора,
   SYSTEM или root либо чужие данные.
2. **Сторонние источники**, из которых скрипт скачивает исполняемые файлы,
   код и списки: GitHub-релизы, автор списка GeoBlock, автор подписки, сам этот
   репозиторий.
3. **Оператор сервера туннеля** — видит трафик, который в туннель уходит.
4. **Сеть и провайдер** — против них и работает обход; TLS-трафик
   расшифровать они не могут.

## 1. Устранено

### F-01. Драйвер ядра загружался из каталога, доступного на запись — КРИТИЧЕСКИЙ

*Windows. Проверено на системе 2026-11-03.*

Служба `WinDivert` указывала на файл драйвера в рабочей папке, которую мог
изменить любой вошедший пользователь. Подпись драйверов Windows не мешает
подменить файл другим, легитимно подписанным, но уязвимым драйвером (техника
BYOVD) — это выполнение кода в ядре.

**Сейчас:** драйвер и служба — только в `System32\Zapret2Windows`; при
установке служба, указывающая в другое место, пересоздаётся.

### F-02. Lua, списки и фильтры загружались из каталога, доступного на запись — ВЫСОКИЙ

*Windows. Проверено на системе 2026-11-03.*

`winws2` с правами администратора загружал Lua-код из рабочей папки. Lua в
zapret2 видит и меняет перехваченные пакеты, то есть подмена файла давала
привилегированный перехват трафика.

**Сейчас:** все ресурсы `winws2` берутся из `System32\Zapret2Windows`
(Windows) и `/opt/zapret2` (Linux, владелец root, права 755).

### F-04. Неполное удаление — СРЕДНИЙ

*Обе системы. Linux проверен в тестовой среде (1.7.1).*

**Сейчас:** удаление (пункт [10]) останавливает процессы обхода и туннеля,
снимает автозапуск, таймер и задачи, службу WinDivert, удаляет рабочий каталог
(на Windows — с проверкой точного пути), блок `hosts`, правила NRPT, и в конце
показывает проверку остатков. Повторный запуск безопасен.

Остаток на Windows: резервная копия `hosts.zapret-backup` не удаляется (на
Linux копия удаляется с 1.7.1).

### F-16. Остановка задевала посторонние процессы — НИЗКИЙ

*Linux. Найдено и исправлено в 1.7.1, проверено в тестовой среде.*

`pkill -f <путь>` совпадал с любым процессом, в аргументах которого встречался
путь к `nfqws2` или sing-box; в тесте он завершил оболочку, запустившую
скрипт. **Сейчас:** совпадение только с начала командной строки, с ожиданием
выхода и принудительным завершением через 4 секунды.

## 2. Открытые риски

### F-05. Задачи SYSTEM запускают скрипт из каталога, доступного на запись — ВЫСОКИЙ

*Windows. По коду версии 1.8.0.*

Обе задачи планировщика выполняют от имени **SYSTEM** сам файл скрипта —
там, куда его положил пользователь (обычно «Загрузки» или рабочий стол):

- `Zapret2Windows` — при каждом входе в систему, если включён автозапуск;
- `Zapret2WindowsGeoList` — **каждый день; создаётся автоматически при
  включении туннеля** (с версии 1.8.0).

Этот файл может изменить сам пользователь и любая программа, работающая от
его имени. Изменённый файл выполнится как SYSTEM — полное повышение прав.

**С версии 1.8.0 риск вырос:** раньше для него нужно было включить автозапуск,
теперь достаточно включить туннель.

На Linux этой проблемы нет: службы и таймер запускают только файлы из
`/opt/zapret2`, принадлежащие root, а для таймера скрипт копируется в
`/opt/zapret2/tunnel/`.

**Рекомендация:** при создании задач копировать скрипт в
`System32\Zapret2Windows` и указывать задачам копию — как это уже сделано на
Linux. До исправления: держите скрипт в каталоге, куда обычный пользователь
писать не может, или не включайте туннель и автозапуск на компьютере, где
работают другие пользователи.

### F-17. Ключи и пароли профилей туннеля читаются любым пользователем — СРЕДНИЙ

*Windows. По коду; права выведены из наследования, на системе не проверены.*

Профили хранятся в `System32\Zapret2Windows\tunnel\profiles.json`, конфиги — в
`config.json` и `xray.json` рядом. Там закрытые ключи WireGuard, UUID VLESS,
пароли Trojan и Shadowsocks. Скрипт не задаёт права на каталог, поэтому
действуют унаследованные от `System32`: группа «Пользователи» может их
**читать**. Любой локальный пользователь может забрать учётные данные VPN.

На Linux эти файлы создаются с правами 600 (только root).

**Рекомендация:** при создании каталога `tunnel` оставлять доступ только
Administrators и SYSTEM.

### F-06. Скачанные исполняемые файлы не сверяются с контрольными суммами — СРЕДНИЙ

*Обе системы. По коду.*

| Что | Версия | Проверка |
|---|---|---|
| zapret2 (`winws2`/`nfqws2`, WinDivert, Lua) | закреплена: v1.0.6 | только HTTPS |
| sing-box | закреплена: 1.14.4 | только HTTPS |
| xray-core | **не закреплена: последний выпуск** | только HTTPS |

HTTPS к `github.com` защищает от подмены в сети, но не от подменённого выпуска
у источника. Все эти файлы запускаются с правами администратора или root.
xray-core без закреплённой версии меняется без изменения скрипта, и
несовместимый выпуск может сломать профили с XHTTP.

**Рекомендация:** закрепить версию xray-core и сверять SHA-256 всех загрузок
со значениями, записанными в скрипте.

### F-18. Самообновление без подписи — СРЕДНИЙ

*Обе системы. По коду.*

Пункт [9] скачивает скрипт из ветки `main` этого репозитория и проверяет
только синтаксис и номер версии. Тот, кто может записать в `main` (владелец
аккаунта, похищенный токен, слитый без проверки PR), получает выполнение кода
с правами администратора или root у всех, кто обновится. Из той же ветки
сценарий публикует релизы (F-23).

**Рекомендация:** двухфакторная аутентификация на GitHub, защита ветки `main`,
просмотр каждого PR перед слиянием — включая PR от ассистентов.

### F-20. Доверие оператору туннеля и автору подписки — СРЕДНИЙ

*Обе системы. Присуще схеме.*

- **Оператор сервера** видит по трафику, идущему в туннель, адреса и имена
  сайтов (SNI); содержимое HTTPS ему недоступно, обычный HTTP — доступен
  полностью. В туннель идут сайты из своего списка и из внешнего (F-19).
- **Подписка** — это доверие её автору: он выбирает серверы, а значит, и того,
  кто видит ваш трафик. Бесплатные подписки из открытых источников обычно
  ведут к серверам неизвестных владельцев.
- JSON-конфиги sing-box и Xray переносятся в профиль почти без изменений.
  Описывают они только исходящее соединение, но это всё равно конфиг от
  стороннего лица.

**Рекомендация:** свой сервер или известный провайдер; не импортировать
подписки неизвестного происхождения.

### F-07. Журналы и отчёты раскрывают посещённые ресурсы — СРЕДНИЙ

*Обе системы. По коду.*

- `autohostlist` — по сути история сайтов, к которым не удалось подключиться.
- Windows: журналы `winws2`, sing-box и xray-core лежат в
  `System32\Zapret2Windows\logs`, доступном на чтение всем пользователям.
- Linux: отчёт `report` пишется в `/tmp/zapret2-report-*.txt` с правами 644
  (читают все пользователи). В нём адреса серверов туннеля и до 600 строк
  отладочного журнала `nfqws2` с адресами и содержимым пакетов. Отладочный
  журнал `/tmp/zapret2-nfqws2-debug.log` остаётся после отчёта. Ключей и
  паролей профилей в отчёте нет.

**Рекомендация:** удалять отчёты после отправки; создавать их с правами 600;
ограничить чтение каталога журналов на Windows.

### F-14. Изменение `hosts` и системного DNS — СРЕДНИЙ

*Обе системы. Присуще схеме.*

- **DoH-блок в `hosts`** (пункт [7]) закрепляет адреса статически: адреса CDN
  меняются, устаревшая запись ломает доступ до обновления. Для этих имён
  системный DNS и DNS-фильтры не действуют. Пишутся только домены, для которых
  системный DNS отдаёт неработающий адрес; каждый адрес проверяется
  TLS-соединением с проверкой сертификата.
- **DNS доменов туннеля** уходит в локальный sing-box (Windows — правило NRPT,
  Linux — маршрутные домены systemd-resolved). Правила снимаются при остановке
  туннеля и удалении.
- Целостность HTTPS сохраняется: подменённый адрес не даёт расшифровать трафик.

### F-08. Широкий перехват — широкий радиус сбоя — СРЕДНИЙ

*Обе системы. Присуще схеме.*

Перехват затрагивает все приложения: Windows — исходящие TCP 80/443, UDP 443
и UDP-трафик STUN, Discord и WireGuard на любых портах; Linux — первые пакеты
соединений. Неудачная стратегия ломает посторонние программы.
`--hostlist-auto-retrans-reset=1` намеренно сбрасывает соединения, которые
считает заблокированными. Известны конфликты WinDivert с Hyper-V, WSL2,
VirtualBox, антивирусами и сторонними VPN.

Смягчение: трафик в туннель (диапазон FakeIP) и к серверам туннеля zapret не
трогает; на Windows `winws2` по умолчанию не перехватывает локальную сеть.

### F-09. Риски драйвера ядра — СРЕДНИЙ

*Windows. Присуще схеме.*

WinDivert — подписанный драйвер ядра; антивирусы часто считают его
нежелательной программой. Известны сбои системы при конфликтах с другими
драйверами. Драйвер давно не развивается; уязвимость в нём означала бы
повышение прав до ядра.

### F-10. Правовые и организационные риски — СРЕДНИЙ

- Обход блокировок может нарушать законодательство отдельных стран и правила
  провайдера.
- На рабочем или управляемом устройстве — нарушение политики организации;
  перехват трафика на таком устройстве — отдельный риск.
- Поддельные и переупорядоченные пакеты и сбросы соединений системы
  обнаружения вторжений видят как сетевую атаку.

### F-19. Внешний список решает, какие сайты идут в туннель — НИЗКИЙ

*Обе системы. По коду; Linux проверен на подставных данных.*

Список GeoBlock проекта
[itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains)
обновляется раз в сутки. Его авторы — или тот, кто получит доступ к их
репозиторию, — могут добавить в него популярные домены, и трафик этих сайтов
пойдёт через ваш сервер туннеля: медленнее и на виду у его оператора (F-20).
Перенаправить трафик на сервер злоумышленника или выполнить код список не
может: он задаёт только имена доменов.

Проверки в скрипте: загрузка по HTTPS; каждая строка проверяется как имя
домена; ответ меньше 50 доменов отвергается, остаётся прежняя копия; общее число
доменов туннеля ограничено 1000; свой список туннеля не меняется.
Выключение — пункт [12] меню туннеля.

### F-21. Локальные прокси туннеля без пароля — НИЗКИЙ

*Обе системы. По коду.*

sing-box слушает `127.0.0.1:40480`, xray-core — `127.0.0.1:40482`, при проверке
профилей временно открываются `40481` и `40483`. Пароля нет: любая программа и
любой пользователь этого компьютера могут отправлять трафик через туннель — от
имени адреса сервера. На компьютере с одним пользователем значения не имеет.

### F-22. sing-box и xray-core работают с полными правами — НИЗКИЙ

*Обе системы. По коду.*

На Linux службы туннеля не задают `User=`, поэтому sing-box и xray-core
работают от root; на Windows — от администратора или SYSTEM (при запуске из
задачи автозапуска). sing-box нужны права
только для TUN-адаптера, xray-core — не нужны вовсе, а оба разбирают данные из
сети. Уязвимость в них дала бы полные права.

Для сравнения, штатный init-скрипт zapret2 запускает `nfqws2` с понижением
прав до отдельного пользователя; скрипт эту настройку не меняет.

**Рекомендация (Linux):** для xray-core — `DynamicUser=yes`; для sing-box —
отдельный пользователь с `AmbientCapabilities=CAP_NET_ADMIN`.

### F-11. Постоянные привилегированные компоненты — НИЗКИЙ

Служба WinDivert, задачи планировщика (Windows), службы и таймер systemd
(Linux) остаются в системе до удаления. Полный откат — пункт [10].

### F-12. Запуск в обход политики выполнения PowerShell — НИЗКИЙ

*Windows.*

Скрипт запускается с `-ExecutionPolicy Bypass`, а вариант `.cmd` исполняет
текст файла через `[ScriptBlock]::Create`. Политика выполнения от этого не
защищает. В сочетании с F-05 это усиливает риск.

### F-23. Сценарий выпуска релизов — НИЗКИЙ

*GitHub. По коду сценария.*

`.github/workflows/release.yml` получает право записи в репозиторий
(`contents: write`) и запускается только при изменении `main` или вручную —
не на PR из сторонних копий репозитория, так что чужой код с этим правом не
выполнится. В релиз попадают файлы из `main` как есть, без сборки.
`actions/checkout@v4` подключён по метке версии, а не по хешу коммита.

**Рекомендация:** закрепить `actions/checkout` по хешу коммита; защита `main`
(F-18) защищает и релизы.

### F-13. Граница применимости (не уязвимость)

Для адресов, заблокированных на уровне маршрутизации, обход DPI бессилен;
для этого есть туннель. Подстановка случайных публичных прокси была бы и
риском безопасности, и нарушением — скрипт так не делает.

## 3. Компенсирующие меры

- **Нет TLS-MITM**, корневые сертификаты не устанавливаются, трафик не
  расшифровывается.
- **Защищённые рабочие каталоги:** `System32\Zapret2Windows`
  (запись — только Administrators и SYSTEM) и `/opt/zapret2` (владелец root,
  755).
- **Linux:** постоянные компоненты запускают только файлы из `/opt/zapret2`;
  профили и конфиги туннеля — права 600; в отчёт ключи и пароли не попадают.
- **Туннель только для выбранных сайтов:** в TUN маршрутизируется лишь
  диапазон FakeIP, остальной трафик идёт мимо sing-box.
- **Свои адреса туннеля** (TUN, FakeIP, таблица маршрутов) — без конфликтов с
  другими клиентами sing-box.
- **Профили проверяются движком** (`sing-box check`, `xray run -test`) до
  сохранения.
- **Повышение прав** — штатным запросом UAC или `sudo`/`pkexec`, без обхода.
- **Самообновление** делает резервную копию, проверяет синтаксис нового файла
  и предупреждает об откате версии.
- **Удаление** проверяет остатки и безопасно при повторном запуске.

## 4. Итог и порядок исправлений

Главный открытый риск — **F-05**: на Windows задачи SYSTEM выполняют файл,
который может изменить обычный пользователь. С версии 1.8.0 для этого
достаточно включить туннель. Это полное повышение прав на компьютере, где
работает кто-то ещё, кроме владельца, или где есть вредоносная программа с
правами пользователя.

Рекомендуемый порядок:

1. **F-05** — запускать задачи из копии скрипта в защищённом каталоге.
2. **F-17** — закрыть каталог профилей туннеля от чтения пользователями.
3. **F-06** — закрепить версию xray-core, сверять SHA-256 загрузок.
4. **F-18, F-23** — двухфакторная аутентификация, защита ветки `main`,
   закрепление действий GitHub по хешу.
5. **F-07, F-22** — права отчётов и журналов, понижение прав sing-box и
   xray-core.

Проект перехватывает трафик всех приложений и намеренно изменяет пакеты.
Применять его следует осознанно, с учётом правовых и организационных
ограничений (F-10).
