# Аудит безопасности проекта Zapret2 Windows

**Область аудита:** `Zapret2Windows.ps1`, `Zapret2Windows.cmd`, боевой runtime
`C:\Windows\System32\Zapret2Windows`, служба ядра WinDivert, задача автозапуска.
**Дата:** 2026-11-03. **Среда:** Windows 10 22H2 x64, Windows PowerShell 5.1,
zapret2 v1.0.6 (winws2 + WinDivert).

Аудит выполнен по фактическому состоянию системы: проверены ACL каталогов и
файлов, путь загрузки драйвера ядра, содержимое боевого конфига и параметры
задачи автозапуска. Ниже отдельно указано, что **устранено**, а что
**остаётся**.

---

## 1. Устранено в ходе аудита

### F-01. Драйвер ядра загружался из каталога, доступного на запись — КРИТИЧЕСКИЙ

**Было.** Служба ядра `WinDivert` указывала на
`C:\HarnessWorkspace\zapret2-v1.0.6\binaries\windows-x86_64\WinDivert64.sys`.
ACL этого файла содержал `NT AUTHORITY\Прошедшие проверку:(I)(M)` — то есть
**любой прошедший проверку пользователь мог изменить или заменить** файл
драйвера.

**Риск.** Подпись драйверов Windows (DSE) блокирует загрузку произвольного
неподписанного драйвера, но **не** мешает подменить файл на другой, легитимно
подписанный, но уязвимый драйвер — классическая техника BYOVD (Bring Your Own
Vulnerable Driver), ведущая к выполнению кода в ядре. Альтернативно —
срыв загрузки драйвера (отказ в работе обхода, нестабильность).

**Стало.** Служба перерегистрирована на
`C:\Windows\System32\Zapret2Windows\WinDivert64.sys`; ACL: `Users = Read+Execute`.
Проверено: `State=Running`, `PathName=\??\C:\Windows\System32\Zapret2Windows\WinDivert64.sys`.

### F-02. Lua, списки и фильтры грузились из каталога, доступного на запись — ВЫСОКИЙ

**Было.** Боевой `winws2.args` содержал **14 ссылок** на рабочую папку проекта,
включая исполняемые ресурсы:

```
--lua-init=@C:\HarnessWorkspace\runtime\winws2\lua\zapret-lib.lua
--lua-init=@C:\HarnessWorkspace\runtime\winws2\lua\zapret-antidpi.lua
--hostlist=C:\HarnessWorkspace\runtime\winws2\lists\blocked.txt
--hostlist-auto=C:\HarnessWorkspace\runtime\winws2\lists\autohostlist.txt
--wf-raw-part=@C:\HarnessWorkspace\runtime\winws2\windivert.filter\...
```

Каталог `C:\HarnessWorkspace` имеет `NT AUTHORITY\Прошедшие проверку:(I)(M)`.

**Риск.** Инъекция Lua-кода в привилегированный процесс, который одновременно:
работает с правами администратора/SYSTEM, загружает драйвер ядра и имеет полный
перехват сетевого трафика. Lua в zapret2 способен читать реассемблированную
нагрузку (`desync.reasm_data` — например, TLS ClientHello и QUIC Initial),
дропать, модифицировать и подделывать пакеты. Это примитив сетевого
перехвата/подмены с повышенными правами. Дополнительно подмена raw-фильтра
позволяла незаметно расширить зону перехвата.

**Стало.** `0` ссылок на рабочую папку, `14` — на защищённый каталог.

### F-03. Скрипт управления лежал в каталоге, доступном на запись — ВЫСОКИЙ (частично)

**Было.** `C:\HarnessWorkspace\Zapret2Windows.ps1` →
`NT AUTHORITY\Прошедшие проверку:(I)(M)`.

**Риск.** Задача автозапуска выполняет этот файл от имени **SYSTEM**. Любая
замена файла даёт выполнение кода как SYSTEM при следующем входе в систему.
На момент аудита автозапуск **не** был зарегистрирован, поэтому вектор был
латентным, но сама возможность включить его присутствует в меню.

**Стало.** Боевые ресурсы вынесены в защищённый каталог. Сам файл скрипта
по-прежнему лежит в рабочей папке — см. остаточный риск F-05.

### F-04. Неполное удаление следов — СРЕДНИЙ

**Было.** `Uninstall` только останавливал процесс и снимал задачу автозапуска.
Оставались: служба ядра WinDivert (указывающая в рабочую папку), каталог
`System32\Zapret2Windows`, файл драйвера, списки и логи.

**Стало.** Новая команда `Remove-All` останавливает процесс, удаляет задачу,
останавливает и удаляет службу `WinDivert`, удаляет защищённый каталог
(с проверкой точного совпадения пути перед удалением), опционально сохраняет
копию логов. Посторонние файлы в System32 не затрагиваются.

## 2. Реальные риски, которые остаются

### F-05. Скрипт в каталоге с правами Modify для Authenticated Users — ВЫСОКИЙ

Файл `Zapret2Windows.ps1` доступен на запись всем прошедшим проверку
пользователям, а запускается с правами администратора и (при включённом
автозапуске) от SYSTEM.

**Рекомендация.** До включения автозапуска перенести скрипт в защищённый
каталог, например `C:\ProgramData\Zapret2Windows`, с ACL
`Administrators/SYSTEM = Full`, `Users = Read`, либо явно запретить запись
для `Authenticated Users`. Это единственное оставшееся звено, замыкающее
эскалацию до SYSTEM.

### F-06. Нет проверки целостности бинарников — СРЕДНИЙ

Бинарники копируются из релиза без сверки с официальным `sha256sum.txt`.
У `winws2.exe` отсутствует version resource (проверено: `VersionInfo` пуст),
подпись WinDivert не проверяется.

**Рекомендация.** Сверять SHA-256 с релизом GitHub при установке.

### F-07. Логи и списки раскрывают данные о посещённых ресурсах — СРЕДНИЙ

`logs\stdout.log`, `stderr.log` и отладочные логи содержат IP-адреса, порты,
hostname и hex-дампы payload (в отладочном прогоне лог достигал **1.6 МБ**).
`autohostlist.txt` — фактически история неудачных обращений к ресурсам.
Каталог доступен пользователям на чтение (`Users = Read+Execute`).

**Рекомендация.** Ограничить ACL на подкаталог `logs`, не включать
`--debug` в постоянном режиме, ограничить срок хранения.

### F-14. Контроллер изменяет системный файл hosts — СРЕДНИЙ

Для обхода **DNS-блокировок** (провайдер не отдаёт IP вообще — десинхронизация
здесь бессильна) контроллер разрешает имена через DoH и записывает результат
в `C:\Windows\System32\drivers\etc\hosts` размеченным блоком:

```
# --- Zapret2Windows DoH begin ---
<ip>	<domain>
# --- Zapret2Windows DoH end ---
```

Последствия, которые нужно учитывать:
- **Адреса закрепляются статически.** IP CDN меняются; устаревшая запись может
  сломать доступ к сайту, пока блок не обновится (`-Action DohHosts`) или не
  будет удалён (`-Action Uninstall`).
- **DNS-проверка обходится.** Система перестаёт спрашивать DNS для этих имён,
  поэтому локальные политики/DNS-фильтры на них не действуют.
- **Изменяется системный файл** — нужны права администратора; перед правкой
  создаётся резервная копия `hosts.zapret-backup`.
- Целостность HTTPS при этом сохраняется: подмена IP не даёт расшифровать
  трафик, сертификат всё равно проверяется.

**Управление.** Удаляется полностью командой `-Action Uninstall` (шаг 5/5):
удаляются только размеченные блоки — и наш, и блок прежней версии проекта
(`Zapret2 TUI DoH`). Прочие строки hosts не затрагиваются.

### F-15. Неполное покрытие DoH — НИЗКИЙ

Часть CDN-имён не отдаёт A-запись через DoH (`ytimg.com`, `twimg.com`,
`githubassets.com`, `redditstatic.com`, `tiktokcdn.com`, `ttvnw.net`).
Они попадают в отчёт как «нет ответа» и остаются без записи в hosts.
Это не ошибка: такие хосты обычно резолвятся через CNAME или отдают контент
с того же edge, что и основной домен.

### F-08. Широкий перехват — широкий радиус поражения — СРЕДНИЙ

Захватываются TCP 80/443 и UDP 443 в обе стороны, плюс raw-фильтры
STUN / WireGuard / Discord media (WireGuard — на **любых** портах).

Риски доступности:
- неверная стратегия ломает посторонние приложения (фактически наблюдалось:
  HTTP/2 к Discord/Rutracker переставал работать при узком конфиге);
- `--hostlist-auto-retrans-reset=1` намеренно шлёт RST и может сбрасывать
  медленные или теряющие пакеты легитимные соединения;
- перехват WireGuard/UDP может мешать собственному VPN пользователя;
- известны конфликты WinDivert с Hyper-V / WSL / VirtualBox / AV и EDR.

**Смягчение.** `--wf-filter-lan` по умолчанию исключает не-глобальные адреса,
поэтому LAN-трафик не перехватывается.

### F-09. Риски, присущие драйверу ядра — СРЕДНИЙ

WinDivert — подписанный драйвер уровня ядра, который AV/EDR часто
классифицируют как hacktool: ложные срабатывания, карантин, блокировка
загрузки. Документированы BSOD при конфликтах со сторонним kernel-mode ПО.
Драйвер давно не развивается: уязвимость в нём означала бы повышение
привилегий до ядра.

### F-10. Правовые и организационные риски — СРЕДНИЙ

- Обход блокировок может нарушать законодательство в отдельных юрисдикциях
  и правила использования сети (ToS) провайдера.
- На корпоративном или управляемом устройстве это может нарушать политику
  организации; перехват трафика на рабочем устройстве — отдельный риск.
- Отправка поддельных, дублирующих и переупорядоченных пакетов и RST
  выглядит для IDS/IPS как сетевая атака, что может приводить к блокировкам
  на стороне провайдера и к разбирательству со стороны ИБ.

### F-11. Персистентность — НИЗКИЙ

Служба ядра `WinDivert` (тип запуска Manual) остаётся зарегистрированной и
после остановки процесса; задача автозапуска — постоянный привилегированный
компонент. Корректный откат — только через `-Action Uninstall`.

### F-12. Запуск с `-ExecutionPolicy Bypass` — НИЗКИЙ

Обход политики выполнения в сочетании с записываемым путём скрипта усиливает
F-03/F-05. Рекомендация: подписать скрипт и использовать `RemoteSigned`.

### F-13. Граница применимости (не уязвимость) — НИЗКИЙ

Для адресов с полным блоком на маршрутизации (пример: `telegram.org` — TCP
не устанавливается ни на одном IP) DPI-обход бессилен. Попытка «решить» это
подстановкой случайных публичных прокси была бы и риском безопасности, и
нарушением. Граница указана честно и не маскируется.

## 3. Компенсирующие меры (проверено)

- **Нет TLS-MITM** и не устанавливается корневой сертификат: трафик не
  расшифровывается, хранилище сертификатов не изменяется.
- **LAN исключён** по умолчанию (`--wf-filter-lan`).
- **Защищённый каталог** `System32\Zapret2Windows` ограничен:
  Administrators/SYSTEM — полный доступ, Users — только чтение.
- **Автозапуск не зарегистрирован** на момент аудита.
- **Файл hosts изменяется только размеченным блоком DoH** (см. F-14):
  удаляется командой `Uninstall`; прочие записи и настройки DNS не трогаются.
- **`--wf-dup-check`** (по умолчанию включён) предотвращает дублирующие фильтры.
- **Повышение прав** идёт через штатный запрос UAC (`-Verb RunAs`),
  без обхода UAC.

## 4. Итоговая оценка

До аудита проект содержал **два критичных/высоких дефекта**, позволявших
непривилегированному локальному пользователю претендовать на выполнение кода
в ядре (F-01) и в привилегированном сетевом процессе (F-02). Оба **устранены**
переносом боевых ресурсов и драйвера в ACL-защищённый каталог.

Остаточный высокий риск — **F-05**: сам файл скрипта по-прежнему в
записываемом каталоге. Пока автозапуск выключен, это не даёт SYSTEM напрямую,
но при его включении становится полной эскалацией. Перенос скрипта в
защищённый каталог — обязательное условие перед включением автозапуска.

Проект не является средством сокрытия: он выполняет перехват трафика на
уровне ядра и намеренно модифицирует исходящие пакеты. Применять его следует
осознанно, с учётом правовых и организационных ограничений (F-10).
